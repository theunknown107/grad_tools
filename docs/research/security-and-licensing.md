# Security & licensing notes

Licence and supply-chain notes for anything considered for adoption. Verify a
licence at *adoption* time, not just at inspection time.

## Verified this pass (2026-10-09)

- **awesome-freellm-apis** — MIT (README: "MIT © open-free-llm-api"). MIT permits
  reuse with attribution; it is a *data directory*, so "reuse" means referencing
  its findings, not vendoring code. No GradTools code or asset derives from it.
- **freellm.net** — a hosted service, not a licensed artifact. Has its own
  Privacy/Terms/Refund pages (not read in full). Treat as a third-party service;
  send it no keys or student data. Its Playground claims keys are sent
  direct-to-provider and not stored server-side — unverified by us.

## Standing supply-chain rules (from the brief, Phase 6)

- Do not install unverified packages or run remote install scripts blindly.
- Pin/constrain versions per project convention.
- Verify a licence before copying any code or asset; do not copy proprietary
  assets, whole skill repos, or large copyrighted sections into GradTools.
- Never submit credentials, private repo data, student records, tokens, or source
  to an external service to "test" a provider.
- New providers/infra/paid services need explicit approval.
